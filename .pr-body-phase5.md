## Summary

Phase 5 of the spec: local persistence. All browser data now lives in a SQLite database (`~/Library/Application Support/OPENMXC/browser.sqlite`, WAL mode) with versioned migrations, and the sidebar's Library section is live.

**Database layer**
- `Database`: thin sqlite3 wrapper (prepare/bind/query, typed `SQLValue`), `schema_migrations` table, transactional migrations (`DatabaseMigrations.all`).
- Schema per spec §22: `favorites`, `bookmark_folders`, `bookmarks`, `history_visits`, `reading_list`, `downloads`, `browser_windows`, `browser_tabs`, `search_engines` (DuckDuckGo default + Google seeded), `settings`.

**Stores** (`@MainActor`, write-through to SQLite, in-memory `:memory:` databases for tests)
- `HistoryStore` — records successful main-frame navigations only (flag set in `decidePolicyFor`), search, delete, clear all / older-than-date.
- `BookmarkStore` — folders (nested, one level shown in UI), bookmarks with edit/move/delete; deleting a folder moves its bookmarks to the top level (`ON DELETE SET NULL` — the defined policy).
- `ReadingListStore` — add (re-adding marks unread), mark read/unread, remove, search.
- `DownloadStore` — metadata only (no file contents in SQLite, per spec), stale in-progress rows marked failed on launch.
- `FavoritesStore` — now DB-backed (was in-memory in Phase 4), shared app-wide across windows.
- `SearchService` reads the default engine from `search_engines` instead of a hardcoded constant.

**Downloads (real, not just metadata)**
- `WKNavigationResponsePolicy.download` for non-displayable MIME types; `WKDownloadDelegate` saves to `~/Downloads` (unique filenames), tracks progress bytes, records destination/status; cancel routed to the owning tab via `DownloadCoordinator`; Open / Reveal in Finder / Remove in the UI. Added `com.apple.security.files.downloads.read-write` entitlement.

**Session restoration**
- `SessionStore` saves all windows' tabs (URL, pinned, muted, selected index) on `applicationShouldTerminate` and hands saved windows to new `BrowserController`s in creation order.
- Restored tabs load **lazily**: only the selected tab loads its URL; others keep a `pendingURL` that loads on first selection — restoring a 13-tab session no longer spins up 13 WebContent processes at once (directly informed by the Phase 3 memory prototype).

**Library UI** — sidebar Bookmarks / Reading List / History / Downloads open a library view in the content area with search, context menus (Open, Edit, Move to Folder, Mark Read, Delete, Cancel Download…), and Clear History by range (Last Hour / Today / Last 7 Days / All).

**Verification**
- 34 unit tests pass (9 new `DatabaseStoresTests` + 2 session-restore `TabManagerTests`).
- Manual: browsed example.com → History shows it; Bookmarks → "Bookmark This Page" persists; ⌘Q + relaunch restores tabs with the right one selected and loaded.
- Not E2E-tested: an actual file download (store/delegate paths are unit-tested and compile-verified).
